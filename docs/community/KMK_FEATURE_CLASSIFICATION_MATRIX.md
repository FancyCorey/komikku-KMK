# KMK Feature Classification Matrix

Date: 2026-06-26

Status: Phase 1 classification. Documentation-only. No app code changes are approved by this document.

Baseline scope: full KMK fork delta from current/latest Komikku v1.13.6 baseline, not only the latest KMK change set.

Classification labels:

- `stable-personal`: works well enough for personal use, but not necessarily community-ready.
- `experimental-personal`: useful but still risky, rough, or source/device-dependent.
- `community-candidate-after-cleanup`: could be shared after cleanup, tests, docs, and UX/security review.
- `community-candidate-small-extract`: a smaller part may be shareable even if the whole feature is not.
- `ocr-only`: belongs only to the separate OCR build line.
- `internal-diagnostic`: useful for debugging/power users, not normal public UI.
- `remove-or-defer`: likely too risky, stale, or not worth shipping right now.
- `needs-official-pattern-check`: needs verification against current Komikku patterns before cleanup.

## Cross-Cutting Alignment Findings

These findings apply across multiple rows and should be carried into later phases.

### Code Placement And Architecture

- Much of KMK-Recs lives under `app/src/main/java/exh/recs/`, including UI, source orchestration, extension evaluation, recommendation scoring, import/export, and best-version workflows.
- Domain/data layers exist for taste, evaluation, recommendation cache, source fit, links, and quality signals, which is good, but orchestration still appears broad in app-layer screen models.
- OCR lives under `app/src/main/java/exh/ocr/` and should remain separate from the normal KMK-Recs line.

Required later check:

- Compare package/module boundaries against current Komikku/Mihon/TachiyomiSY patterns before refactoring.

### Database And Backup

- Migrations `46.sqm` through `55.sqm` and many new `.sq` files exist.
- Backup/sync additions are present but not fully audited.
- OCR text should be local-only and excluded from backup/sync/export unless explicitly redesigned.

Required later check:

- Phase 3 must classify every table and backup/sync path.

### Strings And UI

- KMK strings are expected to use `KMR` and `i18n-kmk` base resources.
- Several docs show mojibake, and visible strings must be checked separately.
- Recommendation settings likely need organization so daily controls and experimental controls are not mixed.

Required later check:

- Phase 6 and Phase 10 must inspect hardcoded strings and settings patterns.

### Security And Privacy

- Source Evaluation is the primary security-sensitive feature due to temporary install/probe/uninstall.
- Recommendation bundle import is an untrusted-file boundary.
- OCR stores private local recognized text.

Required later check:

- Phase 4 risk review and required risk register.
